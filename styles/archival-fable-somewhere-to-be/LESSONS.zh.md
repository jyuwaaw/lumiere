# 教训（Somewhere to Be，2026-11-09 → 11-23）

[English](LESSONS.md) | **中文**

每条：问题 → 原因 → 下次一开始就怎么做。👤 表示导演在审片时发现的问题。

## 情绪和声音

1. 👤 **“风格不错，但没有节奏，情绪没有变化”**（v1）
   - 原因：没有情绪弧线，整段配乐来自同一个方案。
   - 下次：生成任何东西之前先写好弧线（每段的情绪、速度和时间）；每幕一段配乐；剪辑卡在拍点网格上。
2. **一个长的配乐方案把希望的起势放到了害怕那几句下面**
   - 原因：五段式的 composition plan 会漂，模型自己决定在哪里推高。
   - 下次：每一幕的配乐单独生成，自己放到时间线上。
3. **composition plan 生成的开头有 8–9 秒静音**
   - 下次：短而强的段落用普通 prompt 模式加 `music_length_ms`。
4. 👤 **“配乐听起来像吉他”**（v1）
   - 原因：没有禁用任何乐器；让模型听整片，它把钢琴说成了吉他。
   - 下次：每条配乐 prompt 都写明不要的乐器。问媒体模型时只问一小段单独切出来的片段，问具体的问题，不要让它评整片。
5. 👤 **“硬切那里需要一记带混响的重击”**（v2）
   - 原因：只有数字静音，显得空，不显得有戏。
   - 下次：每个段落交界都设计一个重音。可以接黑场，但得先有东西落地。
6. 👤 **“那一击不在拍上，很僵”**（v2）
   - 原因：按峰值对齐；配乐自己的最后一下下拍被剪掉了；人声避让又在前面挖了个洞，打断了律动。
   - 下次：先剪掉音效的前摇，把它的**起音**对准配乐自己的下拍；让配乐把那一拍播完。
7. 👤 **“敲门声和手对不上”**（v2）
   - 原因：敲门时间是从 2 fps 的帧条上估的。
   - 下次：用相邻帧的相位相关追踪那只手，取运动反向的帧（这次是片段的第 60、67、73 帧），把每下敲门的起音放在对应帧上。
8. **品牌名单独成句时重音很怪**
   - 原因：“CoreSpeed”单独成句时，“Core”的音高冒尖。
   - 下次：把名字放在句子里，或者交给 logo（v2.1 的旁白不念名字）。一定要念的话，量一下重读音节相对整条中位数的音高，高出约 30% 以上就从更平稳的那条里取这句。
9. **做片的人没法用耳朵挑旁白**
   - 原因：做这部片的 agent 听不见。
   - 下次：按测出来的情绪反差和音高峰值挑，然后在每个审核点让人戴耳机听（稿子、每段配乐单听、第一版完整剪辑、细节过一遍、冻结）。上面所有声音问题都是导演发现的，不是 agent。

## 画面

10. **铜版画带纸边，16mm 画面带齿孔和日期戳**
    - 下次：在风格前缀里禁掉纸边、边框、齿孔、日期戳和所有文字。只对真的带纸边的静帧裁到版面：版面检测会把满版图的上沿裁掉。
11. **写着“门一扇扇打开”的片段几乎没动**
    - 下次：写镜头看得见的运动：哪扇门、朝哪个方向、透出什么光（“The nearest door on the right swings wide open toward the camera… Clear, visible door motion”）。
12. **快剪段落不够画面用**
    - 下次：一开始就为快剪规划插入镜头：门闩、锁孔里的眼睛、锁链、钟、满墙的钥匙这类细节。
13. **只报品牌的结尾显得平**
    - v2.1 的结尾回应了恐惧段的一个画面：被锁链锁住的门，回来时变成一副挽具，让人和心智一起拉车。呼应比新画面更有力。

## 工具和工程

14. **重建出来画面一模一样，H.264 字节却不同**
    - 原因：x264 的输出取决于线程数，ffmpeg 默认按 CPU 数设线程，而沙箱的 CPU 数变了。
    - 下次：每个 libx264 调用都固定 `-threads 8`。这样在 8、4、2 核上字节都一致。
15. **VBV 让 x264 变得不确定**
    - 原因：开了 `-maxrate`/`-bufsize` 又用多线程，同一台机器上编两次结果也不同。
    - 下次：不用 VBV；6.5 Mbps 两遍编码自己就能把体积控制住（约 90 MB），画质一样。
16. **沙箱死了两次，工作只在它的磁盘上**
    - 原因：云沙箱在虚拟机层面不可用了，和当时在跑哪一步无关。
    - 下次：每个版本一通过就冻结成包（素材 + 代码 + 校验和 + 预期流哈希）并立刻上传。进行中的工作也要常提交、常上传。
17. **生成文件的链接会过期**
    - 原因：媒体服务的输出链接 7 天后失效。
    - 下次：每个生成的文件立刻下载进项目，并在台账里记下模型、prompt、seed 和 job id。
18. **超过约 100 MB 的上传会被拒**
    - 下次：成片用 6.5 Mbps 两遍编码（106 秒约 90 MB），压缩包拆成 90 MB 的分卷。
19. **只是读了代码，校验那一步就失败了**
    - 原因：`MANIFEST.sha256` 把 `__pycache__` 里的文件也列了进去，用另一个 Python 版本 import 一下 `shots.py` 就把它们改写了。
    - 下次：清单里不要放 `__pycache__`。在那之前，解开的包在跑 `build.sh` 之前不要在里面运行 Python；已经运行过的话，从压缩包里把缓存文件恢复回来。
